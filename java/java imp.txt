 1. WRAPPER CLASSES
--------------------------------------------------------------

What is a wrapper class?
 - Converts a primitive data type into an object.
 - Each primitive has a matching wrapper class:

     Primitive   |  Wrapper Class
     ------------|---------------
     byte        |  Byte
     short       |  Short
     int         |  Integer
     long        |  Long
     float       |  Float
     double      |  Double
     char        |  Character
     boolean     |  Boolean

Need of wrapper classes
 - Java's java.util classes and the Collection Framework work with
   objects, not primitive types.
 - ArrayList, Vector, etc. can store only objects (reference types),
   not primitives.
 - Wrapper classes give an object form for a primitive value when an
   object is required, e.g. for synchronization in multithreading.

Autoboxing
 - Automatic conversion of a primitive into its wrapper class object.
 - Examples: int -> Integer, long -> Long, double -> Double

     int a = 10;
     Integer b = a        // Autoboxing

Unboxing
 - Reverse of autoboxing: wrapper object -> primitive.
 - Examples: Integer -> int, Long -> long, Double -> double

     Integer a = 10;
     int b = a            // Unboxing

Example program

     package genericsAndWrapperClasses;

     public class WrapperClasses {

         public static void main(String[] args) {

             Integer obj = 12;

             Integer obj2 = Integer.valueOf("12");   // String -> Integer
             System.out.println(obj2 * 4);           // Output: 48

             Boolean myBoolean = Boolean.valueOf("false");

             Integer obj3 = 12;     // autoboxing
             int age = obj3;        // unboxing
         }
     }

 - Integer.valueOf("12") converts a String into an Integer object.
 - obj2 * 4 works because Integer is automatically unboxed to int.

 3. GENERICS
--------------------------------------------------------------

What are generics?
 - Allow classes, interfaces and methods to work with different
   data types while providing type safety.
 - Use a type parameter such as T instead of a fixed data type.

Why use generics?
 - Provides type safety.
 - Avoids unnecessary type casting.
 - Makes code reusable.
 - Detects type errors at compile time.
 - Commonly used with collections: ArrayList, HashSet, HashMap.

Without generics (old way)

     ArrayList list = new ArrayList();

     list.add(10);
     list.add("Hello");

     Integer x = (Integer) list.get(0);

 - Type casting is required.
 - Any type can be added, so errors show up only at runtime.

With generics (modern way)

     ArrayList<Integer> list = new ArrayList<>();

     list.add(10);
     list.add(20);

     Integer x = list.get(0);

 - No casting required.
 - Adding a String gives a compile-time error.

Generic class

     class Box<T> {
         T value;

         void set(T value) {
             this.value = value;
         }

         T get() {
             return value;
         }
     }

     class Main {
         public static void main(String[] args) {
             Box<Integer> b = new Box<>();

             b.set(10);

             System.out.println(b.get());     // Output: 10
         }
     }

 - T represents the type, decided when the object is created.

Generic method

     class Demo {
         public static <T> void print(T value) {
             System.out.println(value);
         }

         public static void main(String[] args) {
             print(10);
             print("Hello");
             print(10.5);
         }
     }

 - <T> before the return type declares a generic method.
 - The same method works with different data types.

Bounded generic types
 - A type parameter normally accepts any data type (except
   primitives).
 - To restrict it to certain types only, use a bounded type with the
   "extends" keyword.

     class GenericsClass<T extends Number> {
         // allows Integer, Double, etc.
         // does NOT allow String

         public void display() {
             System.out.println("This is a bounded type generics class.");
         }
     }

 - GenericsClass works only with children of Number
   (Integer, Double, Float, Long ...).

 5. LIST INTERFACE
--------------------------------------------------------------

 - Extends the Collection interface.
 - Ordered collection that allows duplicate elements.
 - Implementations: ArrayList, LinkedList, Stack, Vector.

     import java.util.ArrayList;
     import java.util.List;

     class ListDemo {
         public static void main(String[] args) {
             List<Integer> list  = new ArrayList<>();
             List<Integer> list2 = new ArrayList<>();

             list.add(10);
             list.add(20);
             list.add(30);

             System.out.println(list);                // [10, 20, 30]
             System.out.println(list.size());         // 3
             System.out.println(list.contains(200));  // false

             // list.remove(Integer.valueOf(10));     // removes value 10

             list2.addAll(list);
             System.out.println(list2);               // [10, 20, 30]
         }
     }

 - list.remove(10) removes the element at INDEX 10.
 - list.remove(Integer.valueOf(10)) removes the VALUE 10.
 - addAll() copies all elements of one collection into another.

 7. VECTOR
--------------------------------------------------------------

 - Similar to ArrayList, but synchronizes each individual operation.
 - A lock is applied automatically whenever an operation is done.
 - If one thread is using the Vector, another thread must wait for
   the lock to be released, so Vector is thread-safe.
 - Continuous locking makes Vector slower (less efficient).
 - In ArrayList, methods are not synchronized: faster, but not
   thread-safe.

     import java.util.*;

     class VectorDemo {
         public static void main(String[] args) {
             List<Integer> list = new Vector<>();

             list.add(10);
             list.add(20);
             list.add(30);

             for (int i = 0; i < list.size(); i++) {
                 System.out.println(list.get(i));
             }
         }
     }

     Output:
     10
     20
     30

ArrayList vs Vector

     Feature          |  ArrayList   |  Vector
     -----------------|--------------|----------
     Synchronized     |  No          |  Yes
     Thread-safe      |  No          |  Yes
     Performance      |  Faster      |  Slower

 8. STACK
--------------------------------------------------------------

 - Follows LIFO order (Last In, First Out).
 - Elements are added on top and removed from the top only.

Stack methods
 - void push(E item)  : pushes the item onto the top of the stack
 - E pop()            : removes and returns the top element;
                        throws EmptyStackException if empty
 - E peek()           : returns the top element (does not remove);
                        throws EmptyStackException if empty
 - boolean empty()    : returns true if the stack is empty

     import java.util.*;

     class StackDemo {
         public static void main(String[] args) {
             Stack<Integer> list = new Stack<>();

             list.push(10);
             list.push(20);
             list.push(30);

             while (!list.empty()) {
                 System.out.println(list.pop());
             }
         }
     }

     Output:
     30
     20
     10

 8. Queue Interface
--------------------------------------------------------------
The Queue interface in the Java Collections Framework provides the functionality of the FIFO (First-In-First-Out) queue data structure. It extends the Collection interface.
linked list has implements both list and queue data structure

• boolean add(E e): Inserts the specified element into the queue.
**• boolean offer(E e): Inserts the specified element into the queue. Returns true if the element was added successfully, or false if the queue is full.
• E remove(): Removes and returns the element at the front of the queue. Throws an exception if the queue is empty.
**• E poll(): Removes and returns the element at the front of the queue. Returns null if the queue is empty.
• E element(): Retrieves but does not remove the element at the front of the queue. Throws an exception if the queue is empty.
**• E peek(): Retrieves but does not remove the element at the front of the queue. Returns null if the queue is empty.

 8. ArrayDeque Class
--------------------------------------------------------------
in this type of data structure we can add/remove from both rear and front on the queue. It is like doubly headed queue

Adding Elements:
• addFirst(E e) or offerFirst(E e): Adds an element to the front of the deque.
• addLast(E e) or offerLast(E e): Adds an element to the end of the deque.
Removing Elements:
• removeFirst() or pollFirst(): Removes and returns the element at the front of deque.
• removeLast() or pollLast(): Removes and returns the element at the end of deque.
Accessing Elements:
• getFirst() or peekFirst(): Returns the element at the front of the deque without removing it.
• getLast() or peekLast(): Returns the element at the end of the deque without removing it.

Stack and Queue Operations Using ArrayDeque
Stack Operations:
○ push(E e): Pushes an element onto the stack represented by the deque.
○ pop(): Pops an element from the stack represented by the deque.
Queue Operations:
○ add(E e) or offer(E e): Adds an element to the end of the deque, effectively making it a queue.
○ remove() or poll(): Removes and returns the element at the front of the deque, making it a queue.

 10. The Map Interface
--------------------------------------------------------------

In Java, elements of Map are stored in key/value pairs. Keys are unique values associated with individual Values.
A map cannot contain duplicate keys. And, each key is associated with a single value.

Map Implements:

HashMap
TreeMap
EnumMap
LinkedHashMap
WeakHashMap

• put(K, V) - Inserts the association of a key K and a value V into the map. If the key is already present, the new value replaces the old value.
• putAll() - Inserts all the entries from the specified map to this map.
• putIfAbsent(K, V) - Inserts the association if the key K is not already associated with the value V.
• get(K) - Returns the value associated with the specified key K. If the key is not found, it returns null.
• getOrDefault(K, defaultValue) - Returns the value associated with the specified key K. If the key is not found, it returns the defaultValue.
• containsKey(K) - Checks if the specified key K is present in the map or not.

 11. Comparable and Comparator
--------------------------------------------------------------

To sort custom objects like Student or Employee, we need to provide explicit sorting logic.
To achieve this, Java provides the Comparable and Comparator interfaces. Comparable and Comparator in Java allow us to define custom sorting behavior for objects, including sorting based on multiple data members.

The Comparable Interface

This interface is found in java.lang package and contains only one method named compareTo(Object). It provides a single sorting sequence only, i.e., you can sort the elements on the basis of single data member only. For example, it may be rollno, name, age or anything else.
public int compareTo(Object obj): It is used to compare the current object with the specified object. It returns

• positive integer, if the current object is greater than the specified object.
• negative integer, if the current object is less than the specified object.
• zero, if the current object is equal to the specified object.

IMPORTANT POINTS
--------------------------------------------------------------

KEY POINTS: ARRAYLIST, HASHMAP, HASHSET, TREEMAP, PRIORITYQUEUE

ARRAYLIST

Backed by a dynamic array. Default capacity is 10, allocated on the first add.
Grows by about 1.5x when full: newCap = old + (old >> 1). The elements are copied into a new array.
get(i) and set(i) are O(1). add at the end is amortized O(1).
Add or remove in the middle or at the front is O(n) because elements shift.
contains and indexOf are O(n).
Allows duplicates, nulls and index access. Not thread-safe.
Trap: on a List<Integer>, remove(1) removes the index. Use remove(Integer.valueOf(1)) to remove the value.
Removing inside a for-each loop throws ConcurrentModificationException. Use iterator.remove() or removeIf().
Pre-size with new ArrayList<>(n) if you know the size, to avoid resizing.

HASHMAP

Array of buckets, default capacity 16, load factor 0.75, resize at 12 entries.
Index = (capacity - 1) & (h ^ (h >>> 16)). Capacity is always a power of 2.
Collisions use chaining. A chain becomes a red-black tree at 8 nodes (only if capacity is at least 64, otherwise it resizes). It reverts to a list at 6.
Resize doubles the capacity and redistributes the entries.
get/put are O(1) average, O(log n) worst case.
Keys need equals() and hashCode(), overridden together. Use immutable keys.
One null key allowed. No ordering guarantee. Not thread-safe.
Useful methods: getOrDefault, putIfAbsent, computeIfAbsent, merge, entrySet.
Frequency counting: map.merge(x, 1, Integer::sum).
Grouping: map.computeIfAbsent(k, x -> new ArrayList<>()).add(v).

HASHSET

Backed by a HashMap, with your element as the key.
No duplicates. add() returns false if the element already exists.
Duplicate check uses hashCode() then equals(), so custom objects need both overridden.
add, remove and contains are O(1) average. One null allowed. No ordering.
Use for removing duplicates, fast membership checks, and “contains duplicate” style problems.

TREEMAP

Red-black tree, sorted by key. get, put, remove, containsKey are O(log n).
Keys must be Comparable, or you pass a Comparator to the constructor.
No null keys (with natural ordering).
Navigation methods: firstKey, lastKey, floorKey (largest key <= k), ceilingKey (smallest key >= k), lowerKey (< k), higherKey (> k), headMap, tailMap, subMap.
Uses compareTo/compare for equality, not equals(). Two keys that compare as 0 are treated as the same key.
Use for sorted iteration and range or closest-value queries.
TreeSet is the same idea for sets.

PRIORITYQUEUE

Binary min-heap stored in an array. The head is the smallest element by default.
offer and poll are O(log n). peek is O(1). remove(Object) and contains are O(n).
Iterating or printing is NOT sorted. Only the head is guaranteed to be the smallest.
Max-heap: new PriorityQueue<>(Collections.reverseOrder()).
Custom ordering: new PriorityQueue<>((a, b) -> Integer.compare(b[1], a[1])). Never use a - b, which can overflow.
No null elements. Not thread-safe. Building from an existing collection heapifies in O(n).
Typical uses: top-K elements, merging K sorted lists, Dijkstra, running median, scheduling.

# JAVA LAMBDA EXPRESSIONS – COMPLETE NOTES

## 1. What is a Lambda Expression?

A lambda expression is a short way to implement the single abstract method of a functional interface without writing lengthy code.

Lambda expressions were introduced in Java 8.

Advantages of Lambda Expressions:

1. Reduces boilerplate code.
2. Makes code shorter and easier to read.
3. Helps in collection processing.
4. Makes sorting easier.
5. Supports functional programming.
6. Works with the Java Stream API.
7. Is useful in multithreading and event handling.

Example without Lambda:

```java
Runnable r = new Runnable() {
    public void run() {
        System.out.println("Hello Java");
    }
};

r.run();
```

Example with Lambda:

```java
Runnable r = () -> System.out.println("Hello Java");

r.run();
```

Output:

```text
Hello Java
```

## 2. Syntax of Lambda Expressions

General syntax:

```java
(parameters) -> expression
```

OR

```java
(parameters) -> {
    statements;
}
```

A lambda expression contains three parts:

1. Parameters: Input values.
2. Arrow operator (`->`): Separates parameters from the body.
3. Body: Code to execute.

Examples:

No parameters:

```java
() -> System.out.println("Hello");
```

One parameter:

```java
x -> System.out.println(x);
```

Multiple parameters:

```java
(a, b) -> a + b;
```

Single expression:

```java
n -> n * n;
```

Multiple statements:

```java
(a, b) -> {
    int sum = a + b;
    return sum;
};
```

Rules:

1. If there are no parameters, use empty parentheses `()`.
2. If there is one parameter, parentheses can be omitted.
3. If there are multiple parameters, parentheses are required.
4. A single expression does not require braces or a `return` statement.
5. A block body that returns a value must use `return`.
6. Parameter types can often be inferred by the compiler.

## 3. Functional Interface

A functional interface is an interface that contains exactly one abstract method.

Example:

```java
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}

class Main {
    public static void main(String[] args) {
        Calculator c = (a, b) -> a + b;

        System.out.println(c.add(10, 20));
    }
}
```

Output:

```text
30
```

Explanation:

The `Calculator` interface has one abstract method called `add()`.

The lambda expression `(a, b) -> a + b` provides its implementation.

### @FunctionalInterface Annotation

This annotation tells the compiler to check whether an interface follows the functional interface rules.

Example:

```java
@FunctionalInterface
interface Test {
    void display();
}
```

The annotation is optional but recommended.

A functional interface can contain:

1. Exactly one abstract method.
2. Multiple default methods.
3. Multiple static methods.
4. Methods overriding public methods of the `Object` class, such as `toString()`.

An interface with two unrelated abstract methods cannot be used as a functional interface.

## 4. Examples of Lambda Expressions

### Example 1: No Parameters and No Return Value

```java
@FunctionalInterface
interface Message {
    void display();
}

class Main {
    public static void main(String[] args) {
        Message m = () -> System.out.println("Hello Java");

    }

```

Output:

```text
Hello Java
```

### Example 2: One Parameter

```java
@FunctionalInterface
interface Printer {
    void print(String name);
}

class Main {
    public static void main(String[] args) {
        Printer p = name -> System.out.println(name);

        p.print("Vivu");
    }
}
```

Output:

```text
Vivu
```

### Example 3: Parameter with Return Value

```java
@FunctionalInterface
interface Square {
    int calculate(int n);
}

class Main {
    public static void main(String[] args) {
        Square s = n -> n * n;

        System.out.println(s.calculate(5));
    }
}
```

Output:

```text
25
```

### Example 4: Multiple Statements

```java
@FunctionalInterface
interface Check {
    boolean test(int n);
}

class Main {
    public static void main(String[] args) {
        Check c = n -> {
            if (n % 2 == 0) {
                return true;
            }

            return false;
        };

        System.out.println(c.test(7));
    }
}
```

Output:

```text
true
false
```

The above lambda can be simplified to:

```java
Check c = n -> n % 2 == 0;
```

## 5. Built-in Functional Interfaces

Java provides several built-in functional interfaces in the `java.util.function` package.

Import statement:

```java
import java.util.function.*;
```

### A. Predicate<T>

A `Predicate` accepts one input and returns a boolean value.

Abstract method: `test()`

Example:

```java
Predicate<Integer> p = n -> n > 10;

System.out.println(p.test(15));
System.out.println(p.test(5));
```

Output:

```text
true
false
```

Use: Checking conditions and filtering data.

### B. Function<T, R>

A `Function` accepts one input of type `T` and returns a result of type `R`.

Abstract method: `apply()`

Example:

```java
Function<Integer, Integer> f = n -> n * n;

System.out.println(f.apply(5));
```

Output:

```text
25
```

Use: Transforming one value into another.

### C. Consumer<T>

A `Consumer` accepts one input and returns nothing.

Abstract method: `accept()`

Example:

```java
Consumer<String> c = s -> System.out.println(s);

c.accept("Hello Java");
```

Output:

```text
Hello Java
```

Use: Printing values and performing actions.

### D. Supplier<T>

A `Supplier` takes no input and returns a value.

Abstract method: `get()`

Example:

```java
Supplier<Integer> s = () -> 100;

System.out.println(s.get());
```

Output:

```text
100
```

Use: Supplying values when required.

### E. Runnable

A `Runnable` takes no arguments and returns nothing.

Abstract method: `run()`

Example:

```java
Runnable r = () -> System.out.println("Running");

r.run();
```

Output:

```text
Running
```

### F. Comparator<T>

A `Comparator` compares two objects.

Abstract method: `compare()`

Example:

```java
Comparator<Integer> c =
    (a, b) -> Integer.compare(a, b);
```

Use: Sorting collections according to custom rules.

### G. UnaryOperator<T>

A `UnaryOperator` takes one value and returns a value of the same type.

Example:

```java
UnaryOperator<Integer> square = n -> n * n;

System.out.println(square.apply(4));
```

Output:

```text
16
```

### H. BinaryOperator<T>

A `BinaryOperator` takes two values of the same type and returns a value of that type.

Example:

```java
BinaryOperator<Integer> sum = (a, b) -> a + b;

System.out.println(sum.apply(10, 20));
```

Output:

```text
30
```

### I. BiPredicate<T, U>

A `BiPredicate` takes two inputs and returns a boolean.

Example:

```java
BiPredicate<Integer, Integer> b = (a, c) -> a > c;

System.out.println(b.test(10, 5));
```

Output:

```text
true
```

### J. BiFunction<T, U, R>

A `BiFunction` takes two inputs and returns a result.

Example:

```java
BiFunction<Integer, Integer, Integer> add =
    (a, b) -> a + b;

System.out.println(add.apply(10, 20));
```

Output:

```text
30
```

### K. BiConsumer<T, U>

A `BiConsumer` takes two inputs and returns nothing.

Example:

```java
BiConsumer<String, Integer> c =
    (name, age) -> System.out.println(name + " " + age);

c.accept("Ravi", 20);
```

Output:

```text
Ravi 20
```

### Important Summary

- Predicate → `test()`
- Function → `apply()`
- Consumer → `accept()`
- Supplier → `get()`
- Runnable → `run()`
- Comparator → `compare()`

## 6. Lambda Expressions with Collections

### A. forEach()

The `forEach()` method performs an action on each element of a collection.

Example:

```java
import java.util.*;

class Main {
    public static void main(String[] args) {
        List<Integer> list = Arrays.asList(10, 20, 30, 40);

        list.forEach(n -> System.out.println(n));
    }
}
```

Output:

```text
10
20
30
40
```

Shorter version:

```java
list.forEach(System.out::println);
```

### B. removeIf()

The `removeIf()` method removes elements that satisfy a condition.

Example:

```java
import java.util.*;

class Main {
    public static void main(String[] args) {
        List<Integer> list = new ArrayList<>(
            Arrays.asList(10, 15, 20, 25, 30)
        );

        list.removeIf(n -> n % 2 != 0);

        System.out.println(list);
    }
}
```

Output:

```text
[10, 20, 30]
```

Explanation:

All odd numbers are removed from the list.

### C. replaceAll()

The `replaceAll()` method replaces every element using the given operation.

Example:

```java
import java.util.*;

class Main {
    public static void main(String[] args) {
        List<Integer> list = new ArrayList<>(
            Arrays.asList(1, 2, 3, 4)
        );

        list.replaceAll(n -> n * n);

        System.out.println(list);
    }
}
```

Output:

```text
[1, 4, 9, 16]
```

### A. Sort in Ascending Order

```java
List<Integer> list = new ArrayList<>(

list.sort((a, b) -> Integer.compare(a, b));

System.out.println(list);
```

Output:

```text
[1, 2, 3, 5, 8]
```

### B. Sort in Descending Order

```java
list.sort((a, b) -> Integer.compare(b, a));
```

Output:

```text
[8, 5, 3, 2, 1]
```

### C. Sort Strings Alphabetically

```java
List<String> names = new ArrayList<>(
    Arrays.asList("Ravi", "Aman", "Vivek")
);

names.sort((a, b) -> a.compareTo(b));

System.out.println(names);
```

Output:

```text
[Aman, Ravi, Vivek]
```

class Student {

## 8. Lambda Expressions and Stream API

A stream allows us to process collections using operations such as filtering, mapping, sorting, and reducing.

### A. filter()

The `filter()` method selects elements that satisfy a condition.

Example:

```java
List<Integer> list = Arrays.asList(1, 2, 3, 4, 5, 6);

list.stream()
    .filter(n -> n % 2 == 0)
    .forEach(System.out::println);
```

Output:

```text
2
4
6
```

### B. map()

The `map()` method transforms each element.

Example:

```java
List<Integer> list = Arrays.asList(1, 2, 3, 4);

List<Integer> result = list.stream()
    .map(n -> n * n)
    .toList();

System.out.println(result);
```

Output:

```text
[1, 4, 9, 16]
```

Note: `Stream.toList()` is available from Java 16. For older Java versions, use `collect(Collectors.toList())`.

### C. sorted()

The `sorted()` method sorts elements.

Example:

```java
List<Integer> list = Arrays.asList(5, 2, 4, 1, 3);

list.stream()
    .sorted()
    .forEach(System.out::println);
```

Output:

```text
1
2
3
4
5
```

### D. distinct()

The `distinct()` method removes duplicate elements.

Example:

```java
List<Integer> list = Arrays.asList(1, 2, 2, 3, 3, 4);

list.stream()
    .distinct()
    .forEach(System.out::println);
```

Output:

```text
1
2
3
4
```

### E. limit()

The `limit()` method restricts the number of elements processed.

Example:

```java
list.stream()
    .limit(3)
    .forEach(System.out::println);
```

It processes at most the first three elements of the stream.

### F. count()

The `count()` method counts the elements in a stream.

Example:

```java
long count = list.stream()
    .filter(n -> n > 2)
    .count();

System.out.println(count);
```

### G. reduce()

The `reduce()` method combines elements into a single result.

Example:

```java
List<Integer> list = Arrays.asList(1, 2, 3, 4, 5);

int sum = list.stream()
    .reduce(0, (a, b) -> a + b);

System.out.println(sum);
```

Output:

```text
15
```

### H. Complete Stream Example

```java
import java.util.*;
import java.util.stream.*;

class Main {
    public static void main(String[] args) {
        List<Integer> list = Arrays.asList(1, 2, 3, 4, 5, 6);

        List<Integer> result = list.stream()
            .filter(n -> n % 2 == 0)
            .map(n -> n * n)
            .collect(Collectors.toList());

        System.out.println(result);
    }
}
```

Output:

```text
[4, 16, 36]
```

Explanation:

1. `filter()` selects even numbers.
2. `map()` squares each selected number.
3. `collect()` stores the results in a list.

## 9. Method References

A method reference is a shorter way to refer to an existing method when its signature matches the expected functional interface.

Syntax:

```java
ClassName::methodName
```

OR

```java
object::methodName
```

### A. Reference to a Static Method

```java
Function<String, Integer> f = Integer::parseInt;

System.out.println(f.apply("123"));
```

Output:

```text
123
```

Equivalent lambda:

```java
Function<String, Integer> f = s -> Integer.parseInt(s);
```

### B. Reference to an Instance Method of a Particular Object

```java
list.forEach(System.out::println);
```

Equivalent lambda:

```java
list.forEach(n -> System.out.println(n));
```

### C. Reference to an Instance Method of an Arbitrary Object

```java
Function<String, String> f = String::toUpperCase;

System.out.println(f.apply("java"));
```

Output:

```text
JAVA
```

### D. Constructor Reference

```java
Supplier<ArrayList> s = ArrayList::new;

ArrayList list = s.get();
```

Equivalent lambda:

```java
Supplier<ArrayList> s = () -> new ArrayList();
```

## 10. Variable Capture in Lambdas

A lambda can access local variables from its surrounding method if those variables are final or effectively final.

Example:

```java
class Main {
    public static void main(String[] args) {
        int x = 10;

        Runnable r = () -> System.out.println(x);

        r.run();
    }
}
```

Output:

```text
10
```

A variable is effectively final if it is not reassigned after initialization.

Incorrect example:

```java
int x = 10;

Runnable r = () -> System.out.println(x);

x = 20;
```

This produces a compilation error because `x` is reassigned after being captured by the lambda.

This restriction applies to captured local variables, not to every variable used inside a lambda.

## 11. Lambda vs Anonymous Class

Lambda Expression:

1. Uses shorter syntax.
2. Implements the single abstract method of a functional interface.
3. Does not introduce a new `this` scope.
4. Is useful for short operations.
5. Is commonly used with collections and streams.

Anonymous Class:

1. Usually requires more code.
2. Can implement an interface with multiple abstract methods.
3. Has its own `this` reference.
4. Can contain additional fields and methods.
5. Is useful for more complex implementations.

Example of an anonymous class:

```java
Runnable r = new Runnable() {
    public void run() {
        System.out.println("Hello");
    }
};
```

Equivalent lambda:

```java
Runnable r = () -> System.out.println("Hello");
```

## 12. Common Mistakes

Mistake 1: Missing parentheses when there are no parameters.

Incorrect:

```java
-> System.out.println("Hello");
```

Correct:

```java
() -> System.out.println("Hello");
```

Mistake 2: Using return with a single expression.

Incorrect:

```java
n -> return n * n;
```

Correct:

```java
n -> n * n
```

Mistake 3: Incorrect block body.

Correct:

```java
n -> {
    return n * n;
}
```

Mistake 4: Using the wrong functional interface method.

Predicate uses `test()`.

Function uses `apply()`.

Consumer uses `accept()`.

Supplier uses `get()`.

Runnable uses `run()`.

Mistake 5: Trying to use a lambda with an interface that has multiple unrelated abstract methods.

A lambda requires a functional interface as its target type.

Mistake 6: Modifying a captured local variable.

Captured local variables must be final or effectively final.

## 13. Important Interview Questions

Q1. What is a lambda expression?

A lambda expression is a concise way to implement the single abstract method of a functional interface.

Q2. When were lambda expressions introduced?

Java 8.

Q3. What is a functional interface?

An interface that contains exactly one abstract method.

Q4. Is @FunctionalInterface mandatory?

No. It is optional but recommended.

Q5. Can a lambda have zero parameters?

Yes. Use `() ->`.

Q6. Can a lambda contain multiple statements?

Yes. Use braces, and use `return` when a value must be returned.

Q7. What is Predicate?

A functional interface that accepts one input and returns a boolean using `test()`.

Q8. What is Function?

A functional interface that accepts one input and returns a result using `apply()`.

Q9. What is Consumer?

A functional interface that accepts an input and returns nothing using `accept()`.

Q10. What is Supplier?

A functional interface that takes no input and supplies a value using `get()`.

Q11. What is a method reference?

A concise way to refer to an existing method using the `::` operator.

Q12. What is the Stream API?

An API used to process sequences of elements through operations such as `filter()`, `map()`, `sorted()`, and `reduce()`.

Q13. Can a lambda implement an interface with two abstract methods?

No, not directly, because that interface is not a functional interface.

Q14. Can lambdas access local variables?

Yes, provided captured local variables are final or effectively final.

Q15. What is the difference between map() and filter()?

`map()` transforms each element, while `filter()` selects elements that satisfy a condition.

Q16. What is the difference between a lambda and a method reference?

A lambda defines the behavior directly, while a method reference refers to an existing method whose signature is compatible with the expected functional interface.
