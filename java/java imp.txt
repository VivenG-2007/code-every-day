 1. WRAPPER CLASSES
--------------------------------------------------------------

What is a wrapper class?
 - Converts a primitive data type into an object.
 - Each primitive has a matching wrapper class:

     Primitive   |  Wrapper Class
     ------------|---------------
     byte        |  Byte
     short       |  Short
     int         |  Integer
     long        |  Long
     float       |  Float
     double      |  Double
     char        |  Character
     boolean     |  Boolean

Need of wrapper classes
 - Java's java.util classes and the Collection Framework work with
   objects, not primitive types.
 - ArrayList, Vector, etc. can store only objects (reference types),
   not primitives.
 - Wrapper classes give an object form for a primitive value when an
   object is required, e.g. for synchronization in multithreading.

Autoboxing
 - Automatic conversion of a primitive into its wrapper class object.
 - Examples: int -> Integer, long -> Long, double -> Double

     int a = 10;
     Integer b = a;        // Autoboxing

Unboxing
 - Reverse of autoboxing: wrapper object -> primitive.
 - Examples: Integer -> int, Long -> long, Double -> double

     Integer a = 10;
     int b = a;            // Unboxing

Example program

     package genericsAndWrapperClasses;

     public class WrapperClasses {

         public static void main(String[] args) {

             Integer obj = 12;

             Integer obj2 = Integer.valueOf("12");   // String -> Integer
             System.out.println(obj2 * 4);           // Output: 48

             Boolean myBoolean = Boolean.valueOf("false");

             Integer obj3 = 12;     // autoboxing
             int age = obj3;        // unboxing
         }
     }

 - Integer.valueOf("12") converts a String into an Integer object.
 - obj2 * 4 works because Integer is automatically unboxed to int.

 2. ARRAYLIST (INTRODUCTION)
--------------------------------------------------------------

 - A resizable array in Java.
 - Size grows or shrinks dynamically when elements are added or
   removed (unlike a normal array).
 - Part of the java.util package.
 - Uses ArrayList<Integer>, not ArrayList<int>, because generics
   need wrapper classes (autoboxing converts values automatically).

     import java.util.ArrayList;

     ArrayList<Integer> numbers = new ArrayList<>();

     numbers.add(10);
     numbers.add(20);
     numbers.add(30);

     System.out.println(numbers);

     Output:
     [10, 20, 30]

 3. GENERICS
--------------------------------------------------------------

What are generics?
 - Allow classes, interfaces and methods to work with different
   data types while providing type safety.
 - Use a type parameter such as T instead of a fixed data type.

Why use generics?
 - Provides type safety.
 - Avoids unnecessary type casting.
 - Makes code reusable.
 - Detects type errors at compile time.
 - Commonly used with collections: ArrayList, HashSet, HashMap.

Without generics (old way)

     ArrayList list = new ArrayList();

     list.add(10);
     list.add("Hello");

     Integer x = (Integer) list.get(0);

 - Type casting is required.
 - Any type can be added, so errors show up only at runtime.

With generics (modern way)

     ArrayList<Integer> list = new ArrayList<>();

     list.add(10);
     list.add(20);

     Integer x = list.get(0);

 - No casting required.
 - Adding a String gives a compile-time error.

Generic class

     class Box<T> {
         T value;

         void set(T value) {
             this.value = value;
         }

         T get() {
             return value;
         }
     }

     class Main {
         public static void main(String[] args) {
             Box<Integer> b = new Box<>();

             b.set(10);

             System.out.println(b.get());     // Output: 10
         }
     }

 - T represents the type, decided when the object is created.

Generic method

     class Demo {
         public static <T> void print(T value) {
             System.out.println(value);
         }

         public static void main(String[] args) {
             print(10);
             print("Hello");
             print(10.5);
         }
     }

 - <T> before the return type declares a generic method.
 - The same method works with different data types.

Bounded generic types
 - A type parameter normally accepts any data type (except
   primitives).
 - To restrict it to certain types only, use a bounded type with the
   "extends" keyword.

     class GenericsClass<T extends Number> {
         // allows Integer, Double, etc.
         // does NOT allow String

         public void display() {
             System.out.println("This is a bounded type generics class.");
         }
     }

 - GenericsClass works only with children of Number
   (Integer, Double, Float, Long ...).

 4. JAVA COLLECTION FRAMEWORK
--------------------------------------------------------------

 - A set of interfaces and classes to implement various data
   structures and algorithms.
 - The interfaces provide methods to perform different operations
   on collections.

Main interfaces (hierarchy)

                   Collection
                  /    |     \
               List   Set    Queue
                       |       |
                  SortedSet   Deque


                     Map
                      |
                  SortedMap


                  Iterator
                      |
                 ListIterator

 - Map is separate; it does NOT extend Collection.

Collection interface methods
 - int size()                  : number of elements
 - boolean isEmpty()           : true if no elements
 - boolean contains(Object o)  : true if element is present
 - boolean add(E e)            : adds element; true if collection changed
 - boolean remove(Object o)    : removes a single instance of the element
 - boolean containsAll(Collection<?> c)
                               : true if all elements of c are present

 5. LIST INTERFACE
--------------------------------------------------------------

 - Extends the Collection interface.
 - Ordered collection that allows duplicate elements.
 - Implementations: ArrayList, LinkedList, Stack, Vector.

     import java.util.ArrayList;
     import java.util.List;

     class ListDemo {
         public static void main(String[] args) {
             List<Integer> list  = new ArrayList<>();
             List<Integer> list2 = new ArrayList<>();

             list.add(10);
             list.add(20);
             list.add(30);

             System.out.println(list);                // [10, 20, 30]
             System.out.println(list.size());         // 3
             System.out.println(list.contains(200));  // false

             // list.remove(Integer.valueOf(10));     // removes value 10

             list2.addAll(list);
             System.out.println(list2);               // [10, 20, 30]
         }
     }

 - list.remove(10) removes the element at INDEX 10.
 - list.remove(Integer.valueOf(10)) removes the VALUE 10.
 - addAll() copies all elements of one collection into another.

 6. LINKEDLIST
--------------------------------------------------------------

 - LinkedList class provides the linked list data structure
   (it is a doubly linked list).
 - Elements are not stored together in memory; they are scattered
   and connected through links.

     import java.util.*;

     class LinkedListDemo {
         public static void main(String[] args) {
             List<Integer> list = new LinkedList<>();

             list.add(10);
             list.add(20);
             list.add(30);

             for (int i = 0; i < list.size(); i++) {
                 System.out.println(list.get(i));
             }
         }
     }

     Output:
     10
     20
     30

 7. VECTOR
--------------------------------------------------------------

 - Similar to ArrayList, but synchronizes each individual operation.
 - A lock is applied automatically whenever an operation is done.
 - If one thread is using the Vector, another thread must wait for
   the lock to be released, so Vector is thread-safe.
 - Continuous locking makes Vector slower (less efficient).
 - In ArrayList, methods are not synchronized: faster, but not
   thread-safe.

     import java.util.*;

     class VectorDemo {
         public static void main(String[] args) {
             List<Integer> list = new Vector<>();

             list.add(10);
             list.add(20);
             list.add(30);

             for (int i = 0; i < list.size(); i++) {
                 System.out.println(list.get(i));
             }
         }
     }

     Output:
     10
     20
     30

ArrayList vs Vector

     Feature          |  ArrayList   |  Vector
     -----------------|--------------|----------
     Synchronized     |  No          |  Yes
     Thread-safe      |  No          |  Yes
     Performance      |  Faster      |  Slower

 8. STACK
--------------------------------------------------------------

 - Follows LIFO order (Last In, First Out).
 - Elements are added on top and removed from the top only.

Stack methods
 - void push(E item)  : pushes the item onto the top of the stack
 - E pop()            : removes and returns the top element;
                        throws EmptyStackException if empty
 - E peek()           : returns the top element (does not remove);
                        throws EmptyStackException if empty
 - boolean empty()    : returns true if the stack is empty

     import java.util.*;

     class StackDemo {
         public static void main(String[] args) {
             Stack<Integer> list = new Stack<>();

             list.push(10);
             list.push(20);
             list.push(30);

             while (!list.empty()) {
                 System.out.println(list.pop());
             }
         }
     }

     Output:
     30
     20
     10

 QUICK REVISION POINTS
--------------------------------------------------------------

 - Wrapper classes turn primitives into objects (needed by
   collections).
 - Autoboxing: primitive -> object.  Unboxing: object -> primitive.
 - Generics give type safety, remove casting, catch errors at

 - Bounded types: <T extends Number> restricts allowed types.
 - Collection hierarchy: Collection -> List, Set, Queue.
   Map is separate.
 - List: ordered, allows duplicates (ArrayList, LinkedList,
   Vector, Stack).
 - Vector is synchronized (thread-safe, slower); ArrayList is not.
 - Stack follows LIFO: push, pop, peek, empty.

 8. Queue Interface
--------------------------------------------------------------
The Queue interface in the Java Collections Framework provides the functionality of the FIFO (First-In-First-Out) queue data structure. It extends the Collection interface.
linked list has implements both list and queue data structure

• boolean add(E e): Inserts the specified element into the queue.
**• boolean offer(E e): Inserts the specified element into the queue. Returns true if the element was added successfully, or false if the queue is full.
• E remove(): Removes and returns the element at the front of the queue. Throws an exception if the queue is empty.
**• E poll(): Removes and returns the element at the front of the queue. Returns null if the queue is empty.
• E element(): Retrieves but does not remove the element at the front of the queue. Throws an exception if the queue is empty.
**• E peek(): Retrieves but does not remove the element at the front of the queue. Returns null if the queue is empty.

 8. ArrayDeque Class
--------------------------------------------------------------
in this type of data structure we can add/remove from both rear and front on the queue. It is like doubly headed queue

Adding Elements:
• addFirst(E e) or offerFirst(E e): Adds an element to the front of the deque.
• addLast(E e) or offerLast(E e): Adds an element to the end of the deque.
Removing Elements:
• removeFirst() or pollFirst(): Removes and returns the element at the front of deque.
• removeLast() or pollLast(): Removes and returns the element at the end of deque.
Accessing Elements:
• getFirst() or peekFirst(): Returns the element at the front of the deque without removing it.
• getLast() or peekLast(): Returns the element at the end of the deque without removing it.

Stack and Queue Operations Using ArrayDeque
Stack Operations:
○ push(E e): Pushes an element onto the stack represented by the deque.
○ pop(): Pops an element from the stack represented by the deque.
Queue Operations:
○ add(E e) or offer(E e): Adds an element to the end of the deque, effectively making it a queue.
○ remove() or poll(): Removes and returns the element at the front of the deque, making it a queue.

 9. Java Set Interface
--------------------------------------------------------------
The Set interface of the Java Collections framework provides the features of the mathematical set in Java. It extends the Collection interface.
Unlike the List interface, sets cannot contain duplicate elements.

Set implements:
EnumSet
HashSet - has time complexity of O(1), it helps to make O(n^2) ---> O(n)
LinkedHashSet - does the same work  hashset but uses linkedlist under the hood ---> O(1)
TreeSet - this sorts the hash set and stores and when we display it shows in ascending order ---> O(logn)

• add() - adds the specified element to the set
• addAll() - adds all the elements of the specified collection to the set
• remove() - removes the specified element from the set
• removeAll() - removes all the elements from the set that is present in another specified set
• retainAll() - retains all the elements in the set that are also present in another specified set
• clear() - removes all the elements from the set
• size() - returns the length (number of elements) of the set
• contains() - returns true if the set contains the specified element


class set{
    static void main(String[] args) {
        //Set<Integer> set=new HashSet<>();
        Set<Integer> set=new LinkedHashSet<>();
        set.add(10);
        //set.add(10);
        set.add(20);
        set.add(30);
        set.add(90);
        set.remove(10);
        System.out.println(set);
    }
}

• In Java, HashSet is commonly used if we have to access elements randomly. It is because elements in a hash table are accessed using hash codes.
• The hashcode of an element is a unique identity that helps to identify the element in a hash table.
• HashSet cannot contain duplicate elements. Hence, each hash set element has a unique hashcode.

hashcode(input) ---> output

When using Set and HashSet in Java, for the primitive types we can just use it without worry about how to implement the hashcode and the comparison logic.
But when you want to use the Set with a custom class by putting custom objects into the set, that custom class has to implement the hashCode() and equals() methods in order for the HashSet to work.

 10. The Map Interface
--------------------------------------------------------------

In Java, elements of Map are stored in key/value pairs. Keys are unique values associated with individual Values.
A map cannot contain duplicate keys. And, each key is associated with a single value.

Map Implements:

HashMap
TreeMap
EnumMap
LinkedHashMap
WeakHashMap

• put(K, V) - Inserts the association of a key K and a value V into the map. If the key is already present, the new value replaces the old value.
• putAll() - Inserts all the entries from the specified map to this map.
• putIfAbsent(K, V) - Inserts the association if the key K is not already associated with the value V.
• get(K) - Returns the value associated with the specified key K. If the key is not found, it returns null.
• getOrDefault(K, defaultValue) - Returns the value associated with the specified key K. If the key is not found, it returns the defaultValue.
• containsKey(K) - Checks if the specified key K is present in the map or not.

 11. Comparable and Comparator
--------------------------------------------------------------

To sort custom objects like Student or Employee, we need to provide explicit sorting logic.
To achieve this, Java provides the Comparable and Comparator interfaces. Comparable and Comparator in Java allow us to define custom sorting behavior for objects, including sorting based on multiple data members.

The Comparable Interface

This interface is found in java.lang package and contains only one method named compareTo(Object). It provides a single sorting sequence only, i.e., you can sort the elements on the basis of single data member only. For example, it may be rollno, name, age or anything else.
public int compareTo(Object obj): It is used to compare the current object with the specified object. It returns

• positive integer, if the current object is greater than the specified object.
• negative integer, if the current object is less than the specified object.
• zero, if the current object is equal to the specified object.
